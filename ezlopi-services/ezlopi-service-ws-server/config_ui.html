connecting

Log inthe local API key

The key is printed once on the serial console at boot, in a box headed EzloPi local API key. It is generated on the device and is not known to anyone else. If you provisioned this device through the Ezlo app instead, the app holds the key and it is not printed.

The User field is not checked unless this firmware was built with CONFIG_EZPI_OFFLINE_LOGIN_VERIFY_USER_ID; the key is the credential. Authorisation applies to this browser tab's connection only.

DeviceItemValue

A writable item shows a box. Values are sent with hub.item.value.set; the device decides whether to accept them, and the reply is shown above.

Wi-Fihub.network.get, hub.network.wifi.*

This moves the device to a different network. It cannot do first-time setup: the firmware is station-only, so you are reading this page over the network the device is already on. If the new credentials are wrong the device falls back to the stored network, which is also the only way you get this page back.
SSIDSignalSecurity

Both fields are capped at 31 characters because the firmware copies them into 32-byte buffers (ezlopi_core_wifi.c), and a longer value would be silently truncated rather than refused.

MQTThub.mqtt.config.get / .set / .reset

The device never returns a stored password -- hub.mqtt.config.get answers with a passwordSet flag instead -- so this box shows up empty even when one is set. Leave it empty to keep the existing password.
